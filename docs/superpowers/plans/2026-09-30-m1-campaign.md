# M1 Campaign Skeleton Implementation Plan

> Execute inline with superpowers:executing-plans; checkpoint every task on the existing branch.

**Goal:** Playable Chapter → Preview → Battle → Result → Unlock/Replay loop.
**Architecture:** Declarative campaign data + pure progression/controller + replaceable storage adapter + DOM UI + existing Phaser arena integration.
**Tech Stack:** JavaScript ESM, Node test, Phaser 4.2.1, Vite 8.3.1.
**Spec:** docs/superpowers/specs/2026-09-30-m1-campaign-design.md

## Global Constraints
- Existing branch/PR; retain 1120x540, Scale.NONE, fixed camera and mobile input.
- Six chapters minimum, five stages each, five chapters per visual row.
- Victory-only unlock; persistent/replayable; no rewards/content production.

## Review Focus
- Malformed/obsolete save must recover fresh without crashing.
- Storage denial must leave in-memory progress playable.
- Locked/unknown IDs and out-of-order results must not bypass progression.
- Retry/exit/reentry must not accumulate Phaser listeners or persist stale result.
- DEV fixtures must not read/write the player's formal save.

## Tasks / stable checkpoints
1. Data: src/campaign/data.js, tests/campaignData.test.js, public/campaign/*.svg. Export campaign, orderedChapters(), chapterRows(), findStage(), nextStage(). Verify ownership, unique IDs/images, six chapters in rows 5+1, independent metadata. RED → implement → targeted PASS → commit/push/update progress.
2. Progression/storage: src/campaign/progression.js, persistence.js, tests/campaignProgression.test.js. Export initialProgress(), recordVictory(state,id), stageStatus/chapterStatus, storage load/save. Verify sequential win, loss/draw neutrality via controller later, replay, chapter unlock, corrupted/version/denied save recovery. RED → GREEN → checkpoint.
3. Chapter UI/controller: src/campaign/controller.js, view.js, style.css, tests/campaignNavigation.test.js. Guard locked IDs; render five-column grid with native disabled buttons, central lock and dark images. RED controller tests → GREEN → checkpoint.
4. Stage UI: large selected preview + title + START, five distinct lower cards, BACK. Verify preview doesn't start battle, locked selection/START denied. Targeted + UI smoke → checkpoint.
5. Battle routing: src/campaign/battleFactory.js, src/main.js, minimal ArenaScene init/create seam, tests/campaignBattle.test.js. Create new existing BattleSession from selected stage lineup/formation/duration; retain defaults/canonical fixture. Verify 1-1 and 1-3 identity, independent restart, stats/formations parity. RED → GREEN → checkpoint.
6. Result: ArenaScene delegates authoritative outcome/actions to controller. Victory unlocks exactly once; NEXT goes preview; RETRY same stage; EXIT chapter; defeat/draw no unlock. Targeted navigation outcomes/reload → checkpoint.
7. Full regression/build/review, push source, inspect Actions and public browser smoke; record evidence/commits/limitations in progress/state. Stop pending iPhone acceptance.
